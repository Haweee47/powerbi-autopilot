## 무엇을 봤나

- GitHub 저장소 1,737개를 스캔했고, 그중 Power BI 파일이 있는 저장소는 1,208개였다.
- 수치 분석: PBIX·PBIT 1,756개(구형 1,655개, PBIR 101개)와 PBIP 리포트 폴더 241개(PBIR 158개, 구형 83개)
- 서식 속성 조사: PBIR 형식 PBIX에서 꺼낸 리포트 폴더 99개의 `visual.json` 11,323개
- 눈으로 검토: 점수 상위 저장소의 대시보드 캡처 79장
- 상세 분석: 우수 사례 6개 리포트의 실제 좌표·테마·글자 크기

PBIP 폴더는 대부분 도구 데모나 "비주얼 하나짜리 템플릿"이었다(페이지당 비주얼 중앙값 2.5개).
그래서 디자인 판단보다는 **PBIR 파일 구조의 표본**으로 썼다. 통계는 [design_stats_pbip.md](design_stats_pbip.md)에 있다.

| 페이지당 비주얼 | 10개 | 5.8개 |

- 대부분 기본값을 그대로 쓴다. 1280×720 캔버스 85%, 흰 배경 87%, 테마 글꼴 Segoe UI 85%.
- 곧 없어질 구형 `card`를 쓴 리포트가 1,016개로, 새 `cardVisual`을 쓴 359개보다 훨씬 많다.
- 비주얼 종류 상위권에 장식 요소가 많다: 텍스트 상자 14%, 슬라이서 13%, 카드 12%, 버튼 11%, 도형 9%, 이미지 8%.
- 공식·전문가 쪽은 **비주얼을 적게, 여백을 넓게** 쓴다.
  (표본의 절반 가까이가 data-goblin 템플릿이라 치우침이 있다)

## 2. 눈으로 본 차이 — 세련돼 보이는 리포트의 공통점

좋은 예: [microsoft/ESS](https://github.com/microsoft/ESS), [microsoft/ValueLens](https://github.com/microsoft/ValueLens-for-Microsoft-Copilot),
[Nesma07 Retail Dark](https://github.com/Nesma07/power-bi-retail-sales-dashboard), [usmansafdar09 Marketing](https://github.com/usmansafdar09/Power-BI-VizVerse)

1. **헤더 띠**: 아이콘, 제목, 한 줄짜리 회색 부제를 둔다. 오른쪽에는 기준일이나 필터 버튼을 둔다.
2. **KPI 한 줄**: 같은 크기 카드 4~6개. 작은 라벨, 큰 숫자, 그리고 전년 대비 한 줄(▲▼를 색으로 표시).
3. **모든 비주얼을 같은 모양의 카드에 담는다**: 페이지 배경(연회색 또는 짙은 남색) 위에 한 톤 밝은 카드를 둔다.
   모서리와 간격은 모두 같게 한다.
4. **색은 한 계열에 강조색 하나**: 좋음·나쁨을 나타낼 때만 의미 색을 쓴다.
5. **필터는 따로 모은다**: 오른쪽 세로 패널이나 헤더 줄 하나에 둔다.
6. **차트 제목은 짧게**: 기본 제목("Sum of X by Y")은 그대로 두지 않는다.

피해야 할 것:
- 형광·원색 (예: 검정 바탕에 형광 초록)
- 기본 차트 제목을 그대로 둔 빽빽한 12개 이상 비주얼
- 무지개색 파이
- 책갈피로 같은 자리에 비주얼 여러 벌 겹치기. ValueLens가 이렇게 한다. 파일 구조가 복잡해져 AI가 다루기 어렵다.

참고할 점: 눈에 띄게 멋진 포트폴리오 상당수는 **Figma·PowerPoint로 만든 배경 이미지** 위에 비주얼을 올린 것이다.
예쁘지만 수정할 때마다 이미지를 다시 만들어야 해서 자동화와 맞지 않는다.
→ 우리는 같은 효과를 **테마와 도형**으로 낸다.

## 4. PBIR 파일에서 본 것 — 서식이 비주얼마다 따로 박혀 있다

PBIR 리포트 99개의 `visual.json` 11,323개를 조사했다.

- 새 카드(`cardVisual`)는 79~91%가 값·라벨·채우기·외곽선·테두리·배경·제목·안쪽 여백을 **비주얼마다 직접** 설정한다.
- 막대 차트도 제목 95%, 배경 84%, 테두리 73%를 비주얼마다 설정한다.
- 사용자 테마 54개 중 비주얼별 서식(`visualStyles`)을 정의한 것은 44개다.
  그마저도 `page`·`*`(공통)를 빼면 14~16개 비주얼 종류만 다룬다.
  `textClasses`(제목·콜아웃·라벨·헤더 글자 단계)는 42개가 정의한다.

의미:
- 같은 서식이 비주얼마다 반복되니 파일이 커지고, AI가 읽고 쓸 때 토큰이 많이 든다.
- 색 하나를 바꾸려 해도 모든 비주얼을 고쳐야 한다.
- 따라서 **서식은 테마에서 한 번 정의하고 `visual.json`에는 위치·필드·제목만 두는 방식** 자체가 차별점이다.

## 5. 우리 디자인 규칙 초안

템플릿과 테마 JSON에 반영한다. 숫자는 우수 사례와 통계를 근거로 한 **초안**이며, 스크린샷 리뷰로 조정한다.

| 항목 | 규칙 | 근거 |
|---|---|---|
| 캔버스·그리드 | 1280×720, 모든 좌표는 8의 배수 | 85%가 1280×720, Superstore |
| 여백·간격 | 바깥 여백 32px, 비주얼 간격 16px, 섹션 사이 24px | 전문가 간격 중앙값 32.5, ESS 40/20 |
| 헤더 | 높이 64px. 제목 20pt, 회색 부제 10pt, 오른쪽에 기준일 | ESS·Retail Dark |
| KPI 줄 | `cardVisual` 4~5개, 높이 96~112px. 라벨 10pt 회색, 값 24~28pt, 비교 10pt ▲▼ 색 | ESS·Retail Dark |
| 본문 | 페이지당 데이터 비주얼 5~8개 | 전문가 중앙값 5.8 |
| 컨테이너 | 페이지 배경은 연회색, 카드는 흰색. 테두리 없음, 모서리 8px, 그림자 없음 | ESS #DBDFE4 |
| 색 | 주색 1 + 회색 단계 + 강조색 1. 좋음/보통/나쁨은 테마 `good`·`neutral`·`bad` 키 | 사용자 테마 54개 중 39개가 이 키를 정의 |
| 글자 크기 | 9 · 10 · 12 · 16 · 24 (5단계만) | 직접 지정 크기의 대부분이 8~14 |
| 필터 | 오른쪽 세로 패널 또는 헤더 줄에 슬라이서 2~3개 | ValueLens·ESS |
| 서식 위치 | 테마 `visualStyles`에 page, *, cardVisual, slicer, tableEx, pivotTable, 막대·세로 막대·선, textbox, shape, actionButton | 4절 |
| 금지 | 구형 `card`, 기본 차트 제목, 구성 항목 4개 이상인 파이·도넛, 3D·그라데이션, 책갈피 겹치기, 배경 이미지 의존 | 2절 |

확인이 필요한 것:
- 한글 글꼴. Segoe UI에는 한글 글자가 없어서 다른 글꼴로 대체되어 보인다.
  맑은 고딕 등을 Desktop과 Power BI 서비스에서 실제로 렌더링해 보고 정한다.

## 6. 한계

- 수치로 매긴 품질 점수가 높다고 예쁜 것은 아니다. 점수 상위권에도 투박한 리포트가 섞여 있었다.
  예쁜지는 반드시 스크린샷으로 판단한다.
- 수집한 원본은 재배포하지 않는다. 좋은 예로 든 리포트도 테마나 레이아웃을 그대로 가져오지 않고 **수치만 참고**한다.
  ESS·ValueLens는 MIT 라이선스지만 마찬가지로 수치만 참고한다.
