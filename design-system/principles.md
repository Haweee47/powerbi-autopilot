# 대시보드 디자인 원칙

좋은 대시보드를 **어떻게 구성해야 하는지** 정리한 문서다. 검증된 자료와 우리가 직접 분석한 공개 리포트 1,700여 개를 근거로 했다.
Power BI 템플릿, 테마 JSON, 리뷰 채점표([review-rubric.md](review-rubric.md))가 모두 이 문서를 따른다.

## 0. 대시보드란

> 하나 이상의 목표를 이루는 데 필요한 **가장 중요한 정보**를 **한 화면에** 모아, **한눈에** 살필 수 있게 한 시각 표시. — Few

세 가지 조건이 모두 들어 있다. 가장 중요한 것만, 한 화면에, 한눈에.
그래서 대시보드는 **보고서가 아니다**. 상세는 드릴다운(클릭해서 아래 수준으로 내려가 보는 기능)이나 다른 페이지로 보낸다. (MS: "독자가 모니터링해야 하는 게 아니면 상세를 대시보드에 두지 말라")

## 1. 목적과 독자가 먼저다

- 만들기 전에 답한다: 누가 보는가, 무엇을 결정하는가, 어디서 보는가(큰 모니터, 노트북, 휴대폰). (MS)
- **한 페이지에는 질문 하나.** 그 질문을 한 문장으로 말할 수 없으면 페이지를 나눈다. (DG 스킬)
- 페이지 유형을 정한다. 유형에 따라 밀도와 차트가 달라진다. (MS 스킬)

  | 유형 | 독자 | 밀도 | 주로 쓰는 것 |
  |---|---|---|---|
  | 경영 요약 | 경영진 — 15초 안에 훑음 | 낮음 (시각 묶음 4~6개) | KPI 카드 + 핵심 차트 1개 |
  | 운영 모니터 | 현장 관리자 — 수시로 확인 | 중간 | 상태 타일, 추세, 예외 목록 |
  | 분석 | 분석가 — 파고듦 | 높음 | 필터 레일, 산점도, 행렬 |
  | 서사 | 발표·보고 | 낮음 | 주석 달린 차트, 결론 문장 |

- **3-30-300 규칙**: 3초 안에 핵심을 알고, 30초 안에 필터로 원하는 조각을 보고, 300초 안에 상세까지 간다.
  첫 3초에 필요한 것은 페이지 맨 위에 둔다. (DG 스킬)

## 2. 구성 — 정보의 위계

- **요약 → 맥락 → 상세** 순서로 위에서 아래로 내려간다.
  1. 맨 위: KPI(핵심 성과 지표) 한 줄
  2. 가운데: 추이·비교 차트
  3. 아래: 표·상세 목록 (DG 스킬 영역 3단, MS "좌상단이 가장 높은 수준")
- **좌상단이 가장 무겁다.** 사람은 왼쪽 위에서 읽기 시작한다. 요약형 페이지는 Z자로, 표·필터가 많은 분석형 페이지는 F자로 시선이 흐른다. (MS, MS 스킬)
- **한 페이지에 시각 묶음 7±2개.** 넘으면 작업 기억이 버티지 못한다.
  - 경영 요약은 4~6개로 줄인다.
  - 12개가 넘으면 안티패턴이다. (MS 스킬)
  - 수집한 전문가 리포트의 중앙값은 5.8개였다.
- **KPI는 3~5개.** 8개를 한 줄로 늘어놓으면 아무것도 눈에 띄지 않는다. (MS 스킬 "KPI 융단폭격")
- **숫자 하나를 크게 보여 줄 때는 맥락을 붙인다.** 증감, 목표 대비, 작은 추세선 같은 것이다.
  맥락 없이 숫자만 크게 둔 카드는 페이지의 주인공이 되면 안 된다. (MS 스킬)
- **제목은 인사이트 문장으로 쓴다.** "월별 매출"보다 "8월까지 목표의 95.8% — 가전·패션이 발목"이 낫다.
  차트 종류("막대 차트")를 제목으로 쓰지 않는다. (MS 스킬, IBCS SAY)

## 3. 레이아웃 — 그리드와 여백

- **8px 그리드**: 모든 좌표와 크기는 8의 배수로 한다. 어긋나면 엉성해 보인다. (MS 스킬, 수집 사례 Superstore)
- **여백은 세 단계**. 묶음 안 간격이 묶음 사이 간격보다 반드시 작아야 한다. 이 차이가 곧 위계다. (DG 스킬, MS 스킬)

  | 단계 | 값 | 쓰는 곳 |
  |---|---|---|
  | 묶음 안 | 16px | KPI 카드끼리, 같은 줄의 차트끼리 |
  | 묶음 사이 | 24px | 영역과 영역 사이 |
  | 바깥 여백 | 24~32px | 화면 가장자리 |

- **간격은 모두 같게.** 왼쪽 쌍은 16px인데 오른쪽 쌍은 24px이면 4~8px 차이라도 거슬린다.
  **세로 경계선은 여러 줄에 걸쳐 이어지게** 맞춘다. (DG 스킬)
- **12열 그리드**로 폭을 나눈다: 8+4(핵심 차트 + 보조), 6+6(비교), 4+4+4, 3+3+3+3(KPI). (MS 스킬)
- **테두리보다 여백으로 묶는다.** 8~16px 떨어진 것은 한 무리로, 32px 이상 떨어진 것은 다른 무리로 읽힌다(게슈탈트 근접성). (MS 스킬)
- **필터 위치**: 1~3개면 제목 줄이나 그 바로 아래 한 줄에 둔다. 4개 이상이면 세로 필터 레일로 모은다.
  필터가 좌상단의 가장 좋은 자리를 차지하면 안 된다. (MS 스킬)
- 스크롤 없이 한 화면에 들어오게 한다. (Few #1, MS)

## 4. 차트 선택 — 질문이 형태를 정한다

사람이 가장 빨리, 정확하게 읽는 것은 **길이**와 **2차원 위치**다.
면적과 각도는 느리고 부정확하다. 색은 양이 아니라 **구분**에 쓴다. (NN/g)

| 질문 | 기본 형태 | 피할 것 |
|---|---|---|
| 지금 값은? | KPI 카드 (값 + 증감 + 작은 추세선) | 막대 하나짜리 차트 |
| 목표 대비 어디쯤? | 불릿 차트, 진행 막대 | 계기판(게이지) |
| 시간에 따라 어떻게 변했나 | 선 차트 (6개 이하 기간이면 세로 막대) | 누적 영역, 3D |
| 무엇이 큰가, 순위는? | **정렬된** 가로 막대 | 정렬 안 된 막대, 파이 |
| 기준보다 위·아래? | 발산 막대 (0이나 100%를 가운데) | 기준선 없는 막대 |
| 부분과 전체 | 100% 누적 막대, 항목 5개 이하면 도넛 | 조각 6개 이상인 파이 |
| 두 지표의 관계 | 산점도 | 이중 축(두 y축) 차트 |
| 정확한 값이 필요 | 표 | 값을 모두 적은 차트 |

- **다양함을 위한 다양함 금지.** 같은 질문엔 같은 형태를 쓴다. (Few #6, MS)
- 막대는 0에서 시작한다. 단위가 다른 두 지표는 차트를 나눈다(이중 축 금지). (MS 스킬, dataviz)
- 막대는 기본적으로 값 순서로 정렬한다. 특정 항목을 찾게 하려면 이름 순서로 정렬한다. (MS)

## 5. 숫자와 글자

- **글자 크기는 4단계, 많아야 5단계.** 크기보다 굵기로 먼저 구분한다. (MS 스킬)

  | 역할 | 크기 | 굵기 |
  |---|---|---|
  | 페이지 제목 | 20pt (약 26px) | 600 |
  | 카드·차트 제목, 인사이트 문장 | 12~14pt | 600 |
  | KPI 값 | 24~36pt | 700 |
  | 본문, 축, 범례 | 9~10pt | 400 |
  | 각주, 기준일 | 8~9pt (대비가 충분할 때만) | 400 |

- **최소 9pt**, 글자와 바탕의 명암 대비는 4.5:1 이상. (MS 스킬, WCAG)
- **숫자는 3~4자리 이내로 줄여 쓴다.** "3,400,000"보다 "340만"이 빨리 읽힌다. 소수점은 1자리. (MS, Few #3 "과도한 정밀도")
- **표의 숫자는 오른쪽 정렬, 같은 자릿수 폭 글꼴**(tabular)을 쓴다. 큰 KPI 숫자에는 쓰지 않는다. (MS 스킬, dataviz)
- **한국어 표기**
  - 금액은 억·만 단위를 쓴다: `8.4억`, `5,519만`. 서식 문자열의 `,`로는 1억(10⁸)으로 나눌 수 없으니 표시용 측정값을 따로 만든다.
  - 비율의 차이는 `%p`로, 비율 자체는 `%`로 구분한다.
  - 증감에는 부호와 기호를 붙인다: `▲ 1.5%`, `▼ 7.3%`.
- 기간과 정밀도를 섞지 않는다. 한 화면에 "지난달"과 "올해 누계"가 같은 이름으로 섞이면 안 된다. (MS)

## 6. 색

- **바탕은 중립, 강조색은 하나.** 화면 대부분은 회색 단계로 두고, 색은 주목할 곳에만 쓴다. (MS 스킬, Few #12)
- **색의 역할은 넷**: 구분(범주), 크기(순차, 한 색의 명암), 방향(발산, 두 색 + 회색 가운데), 상태(좋음·주의·나쁨). 한 차트에 역할 하나. (dataviz)
- **범주 색은 7~8개가 상한.** 더 필요하면 "기타"로 묶거나 작은 여러 차트로 나눈다. (MS 스킬, dataviz)
- **색만으로 뜻을 전하지 않는다.** 남성 약 8%가 색각이상이다. 기호·글자·위치를 함께 쓴다. (NN/g, WCAG 1.4.1)
- **의미색은 예약한다.** 초록·빨강·노랑을 장식에 쓰지 않는다. 좋음·나쁨은 테마의 `good`·`bad`에 둔다. (MS 스킬)
- **한국 관례 주의**: 증시에서는 빨강이 상승이지만, 회계에서는 적자(赤字)가 빨강이다.
  경영 대시보드에서 빨강을 "나쁨"으로 쓰되, **항상 ▲▼ 기호와 부호를 함께** 붙여 헷갈리지 않게 한다.
- 팔레트가 색각이상에도 구분되는지는 눈으로 판단하지 말고 **검증 스크립트로 계산한다**. (dataviz)

## 7. 맥락 — 숫자는 비교할 때 의미가 생긴다

- **모든 핵심 숫자에 비교 기준을 붙인다**: 전년 동기, 목표, 평균. 기준 없는 숫자는 좋은지 나쁜지 알 수 없다. (Few #2)
- **시나리오 표기를 통일한다.** IBCS 방식:
  - 실적(AC)은 진한 색 채움, 전년(PY)은 연한 회색, 계획·목표(PL)는 테두리만.
  - 시간은 가로축, 항목 구조는 세로축에 둔다.
- **아직 오지 않은 기간과 비교하지 않는다.** 올해 8월까지의 실적을 작년 12개월 전체와 비교하지 않는다.
  (예제 03 모델의 `실적기간` 열)
- **데이터 기준일을 항상 보여 준다.** 기준일이 없는 운영 화면은 안티패턴이다. (MS 스킬)
- **목표가 정의되지 않은 수준에서는 달성률을 보여 주지 않는다.** 예를 들어 매장별 목표가 없으면 매장 표에 달성률을 넣지 않는다.

## 8. 상호작용

- **필터는 한 줄로, 걸린 필터는 아래 모든 것에 적용한다.** 숫자가 서로 어긋나면 신뢰가 무너진다. 차트마다 따로 거는 필터는 두지 않는다. (dataviz)
- **핵심은 클릭 없이 보여야 한다.** 가장 중요한 인사이트를 책갈피나 드릴스루 뒤에 숨기지 않는다. (MS 스킬)
- **툴팁은 보조 수단이다.** 툴팁에만 있는 값이 없도록 직접 레이블이나 **표 보기**를 함께 둔다. (dataviz)
- 걸린 필터 상태가 보여야 한다. 슬라이서 머리글이나 필터 요약을 쓴다. (MS 스킬)

## 9. 여러 페이지와 이동 (내비게이션)

한 페이지에는 질문 하나(1절). 그러니 질문이 여럿이면 **페이지가 여럿**이 된다.
그때부터 디자인은 화면 한 장이 아니라 **리포트 전체의 흐름**을 다룬다.
어디서 시작하고, 어떻게 옮겨 다니고, 상세로 들어갔다가 어떻게 돌아오는지가 모두 디자인 대상이다.

### 9-1. 페이지 구성

- **요약에서 시작해 깊이 들어간다.** 가장 흔하고 검증된 구성은 이렇다. (MS 스킬 "Executive + Drill")
  1. 요약(첫 화면)
  2. 비교·분석 페이지
  3. 상세 페이지 — 드릴스루로만 들어오고 탭에서는 숨김
  4. 툴팁 페이지 — 숨김
- **페이지마다 유형을 따로 정한다.** 요약 / 모니터링 / 탐색 / 비교 / 서사 가운데 하나를 고른다.
  4페이지가 모두 같은 틀이면 페이지마다 질문을 따로 생각하지 않았다는 신호다. (MS 스킬, DG 스킬)
- **모든 페이지는 같은 톤, 같은 헤더 위치를 쓴다.** 페이지마다 모양이 다르면 리포트 두 개를 이어 붙인 것처럼 보인다. (MS 스킬)
- **페이지 이름은 목적지를 말한다.** "2페이지"가 아니라 "카테고리 분석". 눈에 보이는 탭은 5~7개 이내로 둔다. (MS 스킬)

### 9-2. 이동 수단 고르기

| 하고 싶은 것 | 쓸 기능 | 주의 |
|---|---|---|
| 페이지 사이 이동 | **페이지 선택기** (page navigator) | 페이지를 추가하거나 이름을 바꾸면 자동으로 따라온다. 숨김·툴팁 페이지는 빼도록 설정할 수 있다. 버튼을 하나씩 만드는 것보다 유지보수가 쉽다 |
| 요약에서 특정 항목의 상세로 | **드릴스루** | 선택한 값으로 걸러진 상세 페이지가 열리고, 뒤로 가기 버튼이 자동으로 생긴다. 드릴스루 필드는 1~2개로 두고, 상세 페이지 제목에 선택한 항목을 보여 준다 |
| 보는 지표나 기준 바꾸기 | **필드 매개변수** | 책갈피로 비주얼을 여러 벌 겹쳐 두지 않고 비주얼 하나로 해결한다. 제약: 암시적 측정값은 쓸 수 없고, 드릴스루·툴팁의 연결 필드로도 쓸 수 없다 |
| 같은 자리에서 보기 전환 (차트↔표, 패널 열고 닫기) | **책갈피** + 선택 창 (+ 책갈피 선택기) | 데이터 옵션을 끈다(필터가 초기화되지 않게). "선택한 비주얼"에만 적용한다 |
| 발표처럼 순서대로 보여 주기 | **페이지 순서 + 페이지 선택기** | 책갈피 슬라이드쇼보다 덜 깨진다 (DG 스킬) |
| 마우스를 올렸을 때 추가 맥락 | **툴팁 페이지** | 320×240 크기, 비주얼 1개 + 카드 1~2개. 상호작용이 안 되고 화면 낭독기가 읽지 못하므로 핵심 정보는 두지 않는다 |
| 고른 값에 따라 다른 페이지로 | **조건부 이동 버튼** (슬라이서 + 이동 대상 조건부 서식) | 버튼 하나로 공간을 아낀다 |
| 계층 아래로 (연 → 월) | **드릴 모드** | 같은 비주얼 안에서 내려간다. 드릴스루와 다르다 |
| 여러 페이지에 같은 필터 | **슬라이서 동기화**, 모든 페이지 필터 | 페이지를 옮겨도 선택 상태가 유지된다 |

### 9-3. 책갈피는 최소한으로

책갈피는 그 순간의 필터와 표시 상태를 통째로 저장한다. 그래서 편리한 만큼 깨지기 쉽다.

- 페이지에 슬라이서를 새로 추가하면 기존 책갈피의 선택 상태가 풀린다. 비주얼 위치는 복원하지 않는다. (MS 이동)
- 한 페이지에 책갈피 선택기가 두 개 이상 있고 서로 같은 설정을 건드리면, 선택 표시가 실제 상태와 어긋난다. (MS 이동)
- **파일이 크다.** 우리가 수집한 PBIR 리포트에서 쟀다.
  - 책갈피 파일 1,009개의 평균은 15KB로, 비주얼 파일 평균 6.5KB의 두 배가 넘는다.
  - 책갈피가 있는 리포트는 책갈피만 합쳐 중앙값 65KB(약 2.2만 토큰), 최대 1.4MB(약 49만 토큰)다.
  - AI가 읽고 고치기에 비싸고, 잘못 고치면 조용히 깨진다.
- 그래서 역할을 나눈다.
  - 지표 전환 → 필드 매개변수
  - 상세 → 드릴스루
  - 순서 있는 이야기 → 페이지
  - 책갈피 → **같은 자리 보기 전환**에만
- 책갈피를 쓴다면 이렇게 한다. (MS 스킬)
  - 5~8개 이내로 둔다.
  - 이름은 내용을 말하게 짓는다 ("책갈피 1" 금지).
  - 목적별로 그룹을 나눈다.
  - "처음 상태로" 책갈피를 하나 둔다.

### 9-4. 이동 UI 디자인

- **자리를 고정한다.** 모든 페이지의 같은 자리에 둔다. 상단 탭 줄이나 왼쪽 세로 레일 가운데 하나다. 현재 페이지는 선택 상태 서식으로 뚜렷하게 표시한다.
- **좌상단 초점 자리는 헤드라인 몫이다.** 이동 UI는 헤더 오른쪽이나 왼쪽 레일에 둔다.
- **드릴스루 페이지에는 두 가지를 둔다.**
  - 뒤로 가기
  - 지금 어디에 있는지 보여 주는 경로 (예: `요약 › 매장 상세 › 일산점`)
- **접근성**: 책갈피 선택기에는 대체 텍스트를 단다. 선택기와 그것이 바꾸는 비주얼은 가까이 두고, 탭 순서는 읽는 순서와 같게 맞춘다. (MS 이동)
- **휴대폰**: 선택기와 버튼은 가로 한 줄로 둔다. (DG 스킬)

### 9-5. 수집 데이터로 본 현실

PBIR 형식 리포트 259개 기준이다. 옛 형식은 버튼 수가 적게 잡혀서 제외했다.

| 지표 | 값 |
|---|---:|
| 여러 페이지로 된 리포트 | 65% |
| 그중 리포트 안에 이동 수단(선택기·버튼)이 있는 곳 | 28% |
| 드릴스루 / 툴팁 / 숨김 페이지가 있는 리포트 | 각 17% |
| 책갈피가 있는 리포트 | 24% (있을 때 중앙값 5개, 최대 72개) |
| 페이지 선택기 / 책갈피 선택기를 쓰는 리포트 | 5% / 7% |

페이지는 여러 개인데 **이동은 설계하지 않은 리포트가 대부분**이다. 이동 설계가 곧 차별점이다.

## 10. 화면 크기 — 반응형과 모바일

- **Power BI는 데스크톱 페이지를 휴대폰에 맞춰 자동으로 재배치하지 않는다.**
  휴대폰 화면은 비주얼을 골라 따로 배치해야 하고, 그러지 않으면 가로 화면을 돌려서 보여 준다. (DG 스킬)
- 휴대폰에는 핵심 **4~8개**만 한 열로 쌓는다. 순서는 KPI → 핵심 차트 → 주요 필터 순이다. 넓은 표, 산점도, 복잡한 행렬은 뺀다. (DG 스킬)
- HTML 시안은 폭에 따라 12열 → 2열 → 1열로 바뀌게 만들어 두면 Power BI 휴대폰 화면 설계에 그대로 쓸 수 있다.
