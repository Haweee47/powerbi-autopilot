# 페이지 레이아웃 템플릿

HTML 시안은 스크롤되지만 **Power BI 페이지는 1280×720 한 화면**이다.
시안 v2의 요약 페이지는 높이가 약 1,500px였다. 그대로 옮기면 우리 원칙이 막겠다고 한 Few의 1번 함정(한 화면을 넘어감)에 걸린다.
그래서 페이지 유형마다 **고정 캔버스에 맞춘 좌표 틀**을 따로 만들었다.

## 격자

| 항목 | 값 | 이유 |
|---|---|---|
| 캔버스 | 1280 × 720 | 수집한 리포트의 85%가 이 크기 |
| 바깥 여백 / 간격 | 24 / 16 | 1280에서 12열이 **정확히 88px**로 나뉜다. 모든 좌표가 정수이자 8의 배수가 된다 |
| 가로 띠 | 이동 16~56 · 헤더 72~128 · 본문 144~696 | 모든 페이지가 같은 띠를 쓰니 페이지 선택기와 제목이 늘 같은 자리에 온다 |

좌표는 `열(col) · 폭(span)`으로 적는다. 픽셀은 스크립트가 계산한다.
사람도 AI도 "3열짜리 카드 4개"처럼 생각하고, 좌표 계산은 하지 않는다.

```
x = 24 + (col − 1) × (88 + 16)
w = span × 88 + (span − 1) × 16
```

## 페이지 유형 4가지

| 요약 (경영 요약) | 카테고리 (분석) |
|---|---|
| ![요약](summary.svg) | ![카테고리](category.svg) |
| **매장 (비교)** | **매장 상세 (드릴스루 대상)** |
| ![매장](stores.svg) | ![매장 상세](store_detail.svg) |

- **요약**: KPI 4개(3열씩)와 본문 두 줄(6+6). 6열 경계가 KPI 줄부터 맨 아래까지 한 선으로 이어진다.
- **카테고리**: 작은 여러 차트는 Power BI 선 차트의 "작은 여러 차트" 기능을 쓴다. 비주얼 하나로 12열을 채우고 세로축은 공통이다. 아래 줄은 표(8) + 구성비 변화(4).
- **매장**: 산점도(8) + 주의 목록(4). 아래 순위표(12)는 스크롤되는 표 비주얼로 둔다. 20행을 한 화면에 다 넣지 않는다.
- **매장 상세**: 이동 띠 자리에 페이지 선택기 대신 뒤로 가기와 경로를 둔다. 페이지 선택기에서는 이 페이지를 숨긴다.

## 자동 검사

[`tools/build_layouts.py`](../../tools/build_layouts.py)가 좌표를 풀면서 네 가지를 검사한다. 하나라도 걸리면 실패로 끝난다.

1. 모든 x · y · 폭 · 높이가 8의 배수인가
2. 캔버스 밖으로 나간 영역이 없는가
3. 영역끼리 겹치지 않는가
4. 본문의 줄들이 세로 경계선을 공유하는가 (채점표 B4)

```bash
python tools/build_layouts.py
# [summary] 영역 13개 · 통과 … 열 폭 88px · 문제 0건
```

결과물 `layouts.resolved.json`은 PBIR 생성기가 읽는 좌표 파일이다.
